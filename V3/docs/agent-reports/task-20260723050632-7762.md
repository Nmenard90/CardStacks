# MIG-202b — V3 application shell

## Outcome

Built a V3-native React application shell using the V2 frontend only as a
visual reference. The implementation uses the existing Supabase session
client, does not copy V2 code or dependencies, and does not introduce catalog
or collection business logic.

## Behavior

- Responsive sticky header, desktop sidebar, and open/close/navigate mobile
  navigation.
- Guest, signed-in, and admin-aware navigation.
- Search/Catalog, Collection, Bulk Add, Binders, Master Sets,
  Imports/Exports, Trade Tools, Convention Mode, Profile, and admin-only Admin
  destinations.
- Explicit unavailable panels for unfinished workflows, including catalog
  search rather than an enabled control with no implementation.
- Reusable loading, empty, error, unavailable, and not-found presentations.
- Accessible `status` and `alert` semantics for route loading and error states.
- Reusable card presentation that replaces missing or failed images with an
  accessible fallback.
- Unknown routes return not-found regardless of authentication state.
- Guest UI contains no collection mutation controls.
- V2-recognizable dark surfaces, yellow and blue accents, compact spacing, and
  DM Sans/Space Mono typography.
- Admin status is resolved from the server (`GET /api/v1/me` → `role`) via a
  dedicated `useIsAdmin` hook in `App.tsx`, instead of trusting a
  client-controlled Supabase `app_metadata` claim. Per `.claude/rules/security.md`,
  authorization must derive from verified server state, not client-supplied
  claims; `role` is not present in the Supabase session object at all, so the
  earlier `session.user.app_metadata.role === "admin"` check was dead logic
  that could never grant admin nav. `RouteView` and `AppShell` now receive
  `isAdmin` as an explicit prop instead of deriving it from `session`.

## Tests added

- Navigation visibility for guest, signed-in, and admin sessions.
- Mobile menu open, close, and navigation behavior.
- Loading, empty, and error states.
- Failed-image fallback behavior.
- Guest and signed-in unknown-route behavior.
- Absence of collection-mutating controls for guests.
