# FND-104 — Make API container builds deterministic

## Files changed

- `apps/api/Dockerfile` — installs from the committed frozen lockfile, generates Prisma Client, builds shared/API packages, deploys an isolated production API dependency tree, and starts the compiled server directly with Node.
- `apps/api/package.json` — limits the deployed API workspace package to compiled `dist` output.
- `.dockerignore` — excludes secrets, host dependencies, generated output, caches, Git metadata, and documentation from Docker build contexts.
- `packages/shared/package.json` — explicitly includes compiled `dist` artifacts when pnpm deploys the shared workspace dependency into the API runtime package.
- `docs/agent-reports/task-20260720224549-1e2e.md` — records task verification and limitations.

## Acceptance criteria

- [x] `pnpm-lock.yaml` is copied before dependency installation.
- [x] Dependency installation uses `pnpm install --frozen-lockfile`.
- [x] Every workspace importer manifest represented in `pnpm-lock.yaml` is copied before the frozen install.
- [x] Prisma Client generation is an explicit build step.
- [x] Prisma Client generation does not depend on an excluded or ambient `.env` file, and its placeholder datasource URL is not retained as runtime configuration.
- [x] The runtime stage receives the API-only output of `pnpm deploy --prod`; it does not copy the full monorepo or build toolchain.
- [x] The runtime stage contains no Corepack setup, owns files as the unprivileged `node` user, and runs the API as that user.
- [x] The deployed `@tcg/shared` package explicitly includes its compiled runtime artifacts.
- [ ] A Docker container starts successfully (Docker is not installed in this execution environment).
- [ ] `GET /health` succeeds against the Docker container (Docker unavailable). The equivalent compiled production server startup and HTTP health request succeeded locally.
- [ ] `pnpm prepush` succeeds (`pnpm` is absent from PATH; Corepack cannot provision it in this restricted environment). Focused compilation and API tests passed.
- [ ] Cross-provider re-review is pending Foreman commit/review orchestration. The prior reviewer findings have been addressed.

## Reviewer feedback resolved

- Added a command-scoped placeholder `DATABASE_URL` for `prisma generate`. This removes the build's dependency on a local `.env` while keeping real credentials out of the build context and runtime image configuration.
- Regenerated Prisma Client inside the isolated `pnpm deploy` output because deployment reconstructs `@prisma/client` from the content-addressable store and otherwise restores its ungenerated stub.
- Limited the API package payload to `dist`, and hardened the runtime stage to run only the production deployment as the non-root `node` user.
- Container build/start and containerized `/health` verification remain environment limitations rather than claimed passes; Docker is not installed here.
