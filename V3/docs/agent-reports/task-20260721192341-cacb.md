# task-20260721192341-cacb — MIG-204: Restore collection quantities, conditions, quick add/remove, bulk add, owned-card views

## Summary

This session resumed a worktree where a prior (timed-out) session had already
built the full backend and feature-level implementation. That work was
reviewed, found sound, and kept. The gap found and fixed in this session: the
new collection and bulk-add feature components existed but were never wired
into the app's routing — `/collection` still rendered an old inline read-only
stub (no add/adjust/remove), and `/bulk-add` fell through to the generic
"not available yet" placeholder.

## Files changed this session

- `apps/web/src/pages/collection/CollectionPage.tsx` (new) — thin page wrapper
  around `features/collection/CollectionPanel`, matching the existing
  `SearchPage`/`SetsPage` pattern.
- `apps/web/src/pages/bulk-add/BulkAddPage.tsx` (new) — thin page wrapper
  around `features/bulk-add/BulkAddPanel`.
- `apps/web/src/routes/RouteView.tsx` — `/collection` now renders
  `CollectionPage`; `/bulk-add` now renders `BulkAddPage` instead of the
  unavailable placeholder. Removed the now-dead inline `CollectionRoute`
  stub (read-only list with no write actions) and its supporting
  types/imports (`Card`, `apiGet`, `useEffect`/`useState` in this file).
- `apps/web/src/routes/RouteView.test.tsx` — updated the three tests that
  exercised the old inline stub's behavior (loading/error/item states using
  a raw-array API shape) to match the real `{items, pageInfo}` contract used
  by `CollectionPanel`/`collectionApi.ts`, and added a routing smoke test for
  `/bulk-add`.

## Carried-over work (built in the prior session, verified in this one)

- `apps/api/src/modules/collection/*` — schemas, repository, service, routes

  decrement-to-zero removal, safe removal, bulk add with per-row

  default-bucket key), quantity bounds, sort-field contract, and the bulk-add

- `apps/web/src/features/collection/{CollectionPanel,AddCardPanel,collectionApi}.tsx/.ts`
  and `apps/web/src/features/bulk-add/{BulkAddPanel,bulkAddApi,stagedRows}.tsx/.ts`

  panel, and the keyboard-efficient bulk-add workflow with localStorage-backed
  staged-row recovery.
- No Prisma schema changes were needed or made — `CollectionItem` already had
  the deterministic `@@unique([userId, cardId, variantId, condition,
  storageLocation])` bucket key and `PurchaseLot` model from prior work.
